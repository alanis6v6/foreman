# slim-context：精簡 token

agent 用久了會越讀越多：CLAUDE.md 每踩一個坑加一條、待辦卡只加不刪、日誌整份帶著走。每次開工先吃掉幾萬字，留給真的工作的空間變少，越讀越像在背守則，而且每一輪都在付這筆錢。

## 第一步：量

列出每次開工**一定會讀**的檔案（CLAUDE.md、它 `@` 進來的檔、常駐的 skill 描述），一份一份量字數，排序。
寫下一個預算（例如：必讀合計 2 萬字以內），之後每週量一次。

（真實案例：我們量出來開機必讀 4.3 萬字，最肥的是一份「答應了還沒做」待辦卡，1.3 萬字，佔三成。它本來每條一行，後來每次有進度就往後接一句，沒有人刪。）

## 第二步：分三層

| 層 | 放什麼 | 怎麼進上下文 |
|---|---|---|
| **必讀** | 身分、不能碰的線、現在進行中的事（每件一行） | 開機就讀 |
| **浮現** | 相關才需要的：過去的決定、某個專案的細節、踩坑紀錄 | 用關鍵字搜、或 hook 依訊息內容附上摘要卡 |
| **需要才讀** | 全文、封存、原始資料 | 必讀裡放一份「地圖」，寫清楚什麼在哪 |

**順序**：不常變的放前面、每天會變的放最後。提示快取是從頭比對的，最前面一變，後面整段快取都失效。

## 第三步：瘦身規則

1. **規則跟紀錄分開**：CLAUDE.md 只留「以後要怎麼做」；「那天發生什麼、試了什麼、數字」搬到 `docs/` 的紀錄檔。
2. **待辦卡每件一行**：狀態＋下一步。進度跟過程寫回那件事自己的專案卡。做完就刪。
3. **日誌滾動**：今天全文；前兩天各一小段；更早的搬去週記或封存。
4. **一條規則只寫在一個地方**，其他地方放指向它的連結。
5. **讀檔先定位**：先搜關鍵字找到行號，只讀那一段；同一份檔這一輪讀過就不要再讀。
6. **長產出寫成檔案**，對話裡只放路徑跟三行摘要。
7. **回報設字數上限**：工單寫「15000 字內」「只回傳結構化結果」。
8. **大任務交給新的上下文**（子 agent、背景工人），只拿摘要回來。
9. **skill 描述要短**：描述每次都常駐，本體叫了才讀；範本放附檔。
10. **上下文過一半換新對話**，換之前把要接的寫進檔案（做法見下一節）。

## 上下文過一半：自己摘要、自己換窗

長對話越到後面每一輪越貴，而且自動壓縮的摘要會把細節磨平。與其等它被壓縮，不如自己在一半的時候整理好、換一個乾淨的對話。

1. **量**：Stop hook（每一輪結束跑的小程式）讀對話紀錄最後一則回覆的 usage，`input_tokens + cache_read_input_tokens + cache_creation_input_tokens` 除以視窗大小。過 50% 提醒一次就好。
2. **收到提醒**：把還沒寫進檔案的決定、數字、進行中的事寫好、commit；跟使用者說一聲要換了；開新對話（或重開 session）。這一步就是在摘要上下文：寫進檔案的是整理過的重點，不是逐字稿。
3. **新對話**從精簡過的必讀檔開始。
4. **不要在一件急事、一段還沒講完的討論中間換**：先做完再換。提醒只響一次，要自己記得。
5. **換模型也挑段落結束的時候**：提示快取屬於寫它的模型，換了要整段重新付一次寫入；先 `/compact` 或寫一份短計畫再換（Anthropic〈Which Claude model should you build with?〉「Switch at a natural break」）。

## 不要

- 不要為了省而把「這個人是誰、我們怎麼相處」刪光：那是必讀，省錯地方 agent 會變成只會照規則做事的機器。要瘦的是流水帳跟重複。
- 不要只瘦一次：每週量，超過預算再瘦。
