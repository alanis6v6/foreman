# route-work：誰做什麼

一個貴的總指揮帶幾個便宜的幫手，最常見的浪費不是模型太貴，是**讓錯的人做錯的事**：總指揮自己去大海撈針、工人被叫去查資料、最貴的模型被拿來寫重複的程式。

## 第一次用：先填這張表

把 `ROLES.md` 存在專案根目錄（或你的全域設定），之後每次派工照表走。

| 角色 | 負責 | 你用的是 |
|---|---|---|
| 總指揮 | 懂使用者要什麼、決定方向、寫工單、驗收 | （例：你現在對話的這個模型） |
| 工人 | 一定要碰檔案、跑指令、build、截圖的事 | （例：較便宜的同家模型，跑在背景） |
| 查資料 | 搜尋、讀長文、看影片、比價、整理 | （例：另一家有長上下文或免費額度的模型） |
| 美術指導 | 很吃審美的設計：只出想法，不寫程式 | （例：最強但最貴的模型，只用在少數幾張） |
| 第二意見 | 挑毛病 | （例：另一家模型的免費方案） |

## 規則

1. **工人預設用便宜的等級**。要升級成貴的模型，先問使用者，不要自己加。
2. **查、蒐集、讀網頁先給「查資料」**，工人只做一定要碰檔案的事。總指揮自己寫得出來的小東西（幾行修改、示意頁）自己寫，不派工。
3. **美術指導只想、不寫**：給它使用者的原話、參考圖、現在的程式片段，只問「要給人什麼感覺、哪裡不對、怎麼改」。施工交給工人。
4. **一張工單一個大功能、最多三件事**。估計超過 30 分鐘就拆；先做使用者最想看的那一半。
5. **每張工單、每次叫別的模型，第一句寫它唯一的職責**：「你的唯一職責：……」。角色寫模糊的時候，模型對「自己人」跟「外人」的差別待遇最大，寫清楚就消失。
6. **回報只要結構化狀態與結果，禁止客套與情緒安撫**。背景互相誇來誇去最燒。
7. **上下文過一半就換一個新的對話**：換之前把要記的寫進檔案。
8. **「還是不行」的時候**：先拿出上一次失敗的證據；拿不出來就先查，不要叫使用者再試一次。

## 為什麼

我們一天派七、八張工單、全用預設的最貴模型，一天燒掉週用量的三成多。改成工人用便宜等級、查資料交給別家模型、工單拆小之後，同樣的事少燒一大半。
