# verify：說「做完了」之前

測試全綠、工人說完成，問題還在，這種事很常見。通常不是模型偷懶，是它周圍的東西有洞：工單漏了一條、回報被截斷、它只搜了一個檔。

## 收到回報後，總指揮自己做

1. **對驗收清單**：工單上每一條，在回報裡找得到證據嗎？找不到就是沒做，不是「應該有」。
2. **讀 diff**：改了哪些檔、幾行，合不合理？提案裡寫的每一個要求，去 diff 裡找到對應的那幾行。
   （真實案例：提案寫了「卡片保留手指傾斜效果」，工人做完、測試全過、使用者也合併了，diff 裡根本沒有這段，沒有人發現。）
3. **看回報裡的「做不到／不確定」**：這段要原封不動告訴使用者。
4. **回報說「沒有／找不到」**：不等於真的沒有。先問它搜了哪些檔、哪些分支。
   （真實案例：工人只看了一個檔就回「沒有這個功能」，使用者：「那些我都做了，你讓他仔細看完 repo」。）
5. **回報被截斷**：很長的回報可能只剩最後一段。對一下長度、開頭有沒有在。

## 跟使用者說「好了」要附的

- 測試數字（幾項過、幾項跳過）
- 截圖：哪個尺寸、深淺色
- 會動的東西：錄影，不是截圖
- **沒驗的直接講沒驗**：「模擬器過了，真機沒裝」「只讀了程式，沒有實際跑」
- 已知的小問題

## 不要

- 不要把「工人說完成」轉述成「完成了」。
- 不要用「應該」「大概」帶過沒驗的部分。
- 驗出問題時不要自己偷偷補完就說好了：講出來，再派一張小的修。
